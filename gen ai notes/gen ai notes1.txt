Step 1: Import ChatOllama

This imports LangChain's wrapper for Ollama.

It allows LangChain to communicate with an Ollama model running on your computer.

Step 2: Load the model
llm = ChatOllama(
    model="llama3.2:1b",
    temperature=0
)

This tells LangChain:

"Use the local Ollama model named llama3.2:1b."

Internally it sends requests to the Ollama server (typically running at http://localhost:11434).

# config/logging_config.py


import logging
import os

from logging.handlers import RotatingFileHandler

LOG_DIR = "logs"

os.makedirs(LOG_DIR, exist_ok=True)

LOG_FILE = os.path.join(LOG_DIR, "app.log")


def setup_logger():

    logger = logging.getLogger("RAG")

    logger.setLevel(logging.INFO)

    if logger.handlers:
        return logger

    formatter = logging.Formatter(
        "%(asctime)s | %(levelname)s | %(filename)s | %(message)s"
    )

    file_handler = RotatingFileHandler(
        LOG_FILE,
        maxBytes=5 * 1024 * 1024,
        backupCount=5
    )

    file_handler.setFormatter(formatter)

    console_handler = logging.StreamHandler()

    console_handler.setFormatter(formatter)

    logger.addHandler(file_handler)
    logger.addHandler(console_handler)

    return logger


logger = setup_logger()

Good question. `__init__.py` is used to tell Python that a directory should be treated as a **package**. It also lets you control what gets imported when someone imports the package.

## Without `__init__.py`

Suppose you have:


rag-enterprise/
│
├── config/
│   ├── settings.py
│   └── logging_config.py


To use `settings`, you write:


from config.settings import settings
from config.logging_config import logger


This works in modern Python (3.3+) because of namespace packages, but you don't have a central place to initialize or expose common objects.

---

## With `__init__.py`


config/
│
├── __init__.py
├── settings.py
└── logging_config.py


**config/**init**.py**


from .settings import settings
from .logging_config import logger


Now you can simply write:


from config import settings, logger


instead of:


from config.settings import settings
from config.logging_config import logger


This is cleaner and easier to maintain.

## Real-world use

Frameworks and large projects commonly use `__init__.py` to:

* Expose frequently used classes and functions.
* Initialize package-level configuration.
* Define package metadata such as `__version__`.
* Keep imports organized and consistent.

For example:


# database/__init__.py

from .postgres import Database
from .history import ChatHistory


Then elsewhere:


from database import Database, ChatHistory


instead of:


from database.postgres import Database
from database.history import ChatHistory


---

## Should every folder have `__init__.py`?

For a production project, it's a good practice to include it in folders that contain Python modules, such as:


config/
services/
loaders/
vectorstore/
database/
memory/
cache/
utils/
api/


You **don't** need `__init__.py` in folders that only store data or assets, such as:


documents/
uploads/
logs/
vector_db/
tests/   # optional; many projects omit it unless tests are imported as a package


For enterprise applications, using `__init__.py` consistently makes imports cleaner, improves readability, and keeps the project structure organized.

# 1. pdf_loader.py


from pathlib import Path

from langchain_community.document_loaders import PyPDFLoader
from langchain_core.documents import Document

from config import logger


class PDFLoader:

    def load(self, file_path: str) -> list[Document]:

        path = Path(file_path)

        if not path.exists():
            raise FileNotFoundError(file_path)

        logger.info(f"Loading PDF: {file_path}")

        loader = PyPDFLoader(str(path))

        documents = loader.load()

        logger.info(f"Loaded {len(documents)} pages")

        return documents

# 4. web_loader.py


from langchain_community.document_loaders import WebBaseLoader
from langchain_core.documents import Document

from config import logger

# What does a `Document` look like?

Every loader returns the same type:


Document(
    page_content="This is the text extracted from the source...",
    metadata={
        "source": "documents/sample.pdf",
        "page": 0
    }
)


Because all loaders return `Document` objects, the next stage (chunking) can process them identically, regardless of their original source.

# splitter.py


from langchain_core.documents import Document
from langchain_text_splitters import RecursiveCharacterTextSplitter

from config import logger


class TextChunker:
    """
    Splits LangChain Document objects into smaller chunks.
    """

    def __init__(
        self,
        chunk_size: int = 1000,
        chunk_overlap: int = 200,
    ):
        self.splitter = RecursiveCharacterTextSplitter(
            chunk_size=chunk_size,
            chunk_overlap=chunk_overlap,
            length_function=len,
            separators=[
                "\n\n",
                "\n",
                ". ",
                " ",
                ""
            ],
        )

    def split_documents(
        self,
        documents: list[Document],
    ) -> list[Document]:

        logger.info(
            f"Splitting {len(documents)} document(s)..."
        )

        chunks = self.splitter.split_documents(documents)

        logger.info(
            f"Created {len(chunks)} chunks."
        )

        return chunks

# What are Embeddings?

Suppose you have three chunks:


Chunk 1:
AWS provides cloud services.

Chunk 2:
Python is a programming language.

Chunk 3:
Snowflake is a cloud data warehouse.


The embedding model converts them into vectors like:


Chunk 1
[0.12, -0.45, 0.77, ...]

Chunk 2
[0.81, 0.22, -0.19, ...]

Chunk 3
[-0.34, 0.11, 0.92, ...]


These vectors capture semantic meaning. Similar content ends up with similar vectors, enabling similarity search.

# embedding_model.py


from langchain_ollama import OllamaEmbeddings

from config import logger, settings


class EmbeddingModel:
    """
    Singleton wrapper around the Ollama embedding model.
    """

    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)

            logger.info(
                f"Loading embedding model: {settings.EMBEDDING_MODEL}"
            )

            cls._instance.model = OllamaEmbeddings(
                model=settings.EMBEDDING_MODEL,
                base_url=settings.OLLAMA_BASE_URL,
            )

        return cls._instance

    def get_model(self):
        return self.model

# How it works


class Singleton:

    _instance = None

    def __new__(cls):

        if cls._instance is None:

            cls._instance = super().__new__(cls)

        return cls._instance


### First call


obj1 = Singleton()


* `_instance` is `None`
* Create a new object
* Store it in `_instance`
* Return it

### Second call


obj2 = Singleton()


* `_instance` already exists
* Don't create a new object
* Return the existing one

---

# Why use Singleton in a RAG application?

Creating an embedding model or database client can be relatively expensive. Reusing a single instance avoids repeated initialization.

Without Singleton:


embedding1 = OllamaEmbeddings(...)
embedding2 = OllamaEmbeddings(...)
embedding3 = OllamaEmbeddings(...)


This creates three separate client objects.

With Singleton:


embedding = EmbeddingModel()

embedding.get_model()
embedding.get_model()
embedding.get_model()


Only one client is created and reused.

---

# Example from our project

            cls._instance = super().__new__(cls)

            cls._instance.model = OllamaEmbeddings(
                model=settings.EMBEDDING_MODEL,
                base_url=settings.OLLAMA_BASE_URL
            )

        return cls._instance

        return self.model

print(emb1 is emb2)

# When should you use Singleton?

Use it when you need **one shared instance** across the application, for example:

* Logger
* Database connection pool or client
* Configuration/settings object
* Redis client
* Embedding model client
* Vector store manager

Avoid using it for objects that represent independent data, such as:

* User
* Employee
* Order
* Product

Each of those should be a separate instance.

---

# Interview Answer (2–3 lines)

**What is the Singleton Design Pattern?**

The Singleton pattern ensures that a class has only one instance throughout the application and provides a single global access point to that instance. It is commonly used for shared resources such as configuration objects, loggers, database clients, and embedding model clients to avoid unnecessary reinitialization and conserve resources.

# faiss_store.py


from pathlib import Path

from langchain_community.vectorstores import FAISS
from langchain_core.documents import Document

from config import logger, settings
from embeddings import EmbeddingModel


class FAISSStore:
    """
    Wrapper around LangChain FAISS vector store.
    """

    def __init__(self):

        self.embedding = EmbeddingModel().get_model()

        self.index_path = Path(settings.VECTOR_DB_PATH)

        self.vector_store = None

    def create(self, documents: list[Document]):

        logger.info("Creating FAISS index...")

        self.vector_store = FAISS.from_documents(
            documents=documents,
            embedding=self.embedding
        )

        self.save()

        logger.info("FAISS index created successfully.")

    def save(self):

        if self.vector_store is None:
            raise ValueError("Vector store not initialized.")

        self.index_path.mkdir(parents=True, exist_ok=True)

        self.vector_store.save_local(
            folder_path=str(self.index_path)
        )

        logger.info(f"Saved index to {self.index_path}")

    def load(self):

        if not self.index_path.exists():
            raise FileNotFoundError(
                f"Index not found: {self.index_path}"
            )

        self.vector_store = FAISS.load_local(
            folder_path=str(self.index_path),
            embeddings=self.embedding,
            allow_dangerous_deserialization=True
        )

        logger.info("FAISS index loaded.")

    def add_documents(self, documents: list[Document]):

        if self.vector_store is None:
            self.load()

        self.vector_store.add_documents(documents)

        self.save()

        logger.info(f"Added {len(documents)} documents.")

    def similarity_search(
        self,
        query: str,
        k: int = 4
    ) -> list[Document]:

        if self.vector_store is None:
            self.load()

        logger.info(f"Searching: {query}")

        return self.vector_store.similarity_search(
            query=query,
            k=k
        )

# services/rag_service.py


from langchain_core.documents import Document

from config import logger
from models import OllamaModel
from prompts import RAG_PROMPT
from vectorstore import FAISSStore


class RAGService:

    def __init__(self):

        self.vector_store = FAISSStore()

        self.llm = OllamaModel().get_model()

    def ask(
        self,
        question: str,
        k: int = 4
    ) -> str:

        logger.info(f"Question: {question}")

        documents = self.vector_store.similarity_search(
            query=question,
            k=k
        )

        context = self._build_context(documents)

        prompt = RAG_PROMPT.invoke(
            {
                "context": context,
                "question": question
            }
        )

        response = self.llm.invoke(prompt)

        logger.info("Answer generated.")

        return response.content

    @staticmethod
    def _build_context(
        documents: list[Document]
    ) -> str:

        return "\n\n".join(
            document.page_content
            for document in documents
        )

# services/ingestion_service.py


from pathlib import Path

from config import logger, settings
from chunking import TextChunker
from loaders import (
    PDFLoader,
    DocxLoader,
    CSVDocumentLoader,
)
from vectorstore import FAISSStore


class IngestionService:

    def __init__(self):

        self.chunker = TextChunker()

        self.vector_store = FAISSStore()

    def ingest(self, file_path: str):

        path = Path(file_path)

        if not path.exists():
            raise FileNotFoundError(file_path)

        logger.info(f"Ingesting {path.name}")

        documents = self._load_document(path)

        chunks = self.chunker.split_documents(documents)

        if self.vector_store.index_path.exists():

            self.vector_store.add_documents(chunks)

        else:

            self.vector_store.create(chunks)

        logger.info("Ingestion completed.")

    def _load_document(self, path: Path):

        suffix = path.suffix.lower()

        if suffix == ".pdf":
            return PDFLoader().load(str(path))

        elif suffix == ".docx":
            return DocxLoader().load(str(path))

        elif suffix == ".csv":
            return CSVDocumentLoader().load(str(path))

        else:
            raise ValueError(
                f"Unsupported file type: {suffix}"
            )

# api/routes.py


from pathlib import Path
import shutil

from fastapi import (
    APIRouter,
    File,
    UploadFile,
    HTTPException,
)

from config import settings, logger
from services import (
    RAGService,
    IngestionService,
)
from .request_model import QuestionRequest
from .response_model import (
    QuestionResponse,
    UploadResponse,
)

router = APIRouter()

rag_service = RAGService()

ingestion_service = IngestionService()


@router.get("/health")
def health():

    return {
        "status": "UP"
    }


@router.post(
    "/ask",
    response_model=QuestionResponse
)
def ask(request: QuestionRequest):

    try:

        answer = rag_service.ask(
            request.question
        )

        return QuestionResponse(
            answer=answer
        )

    except Exception as error:

        logger.exception(error)

        raise HTTPException(
            status_code=500,
            detail="Internal Server Error"
        )


@router.post(
    "/upload",
    response_model=UploadResponse
)
async def upload(
    file: UploadFile = File(...)
):

    upload_dir = Path(settings.UPLOAD_DIR)

    upload_dir.mkdir(
        exist_ok=True
    )

    file_path = upload_dir / file.filename

    with open(file_path, "wb") as buffer:

        shutil.copyfileobj(
            file.file,
            buffer
        )

    ingestion_service.ingest(
        str(file_path)
    )

    return UploadResponse(
        message="Upload successful"
    )

# Production Best Practices

Instead of one `docker-compose.yml`, many teams use multiple files:


docker-compose.yml
docker-compose.dev.yml
docker-compose.prod.yml


For production, you would also:

* Use a reverse proxy such as Nginx or Traefik.
* Add health checks for each service.
* Store secrets outside `.env` (Docker Secrets, Vault, or cloud secret managers).
* Use named volumes for persistent data (as shown for PostgreSQL and Ollama models).
* Build images in CI/CD and deploy versioned images rather than building on the production server.

This Docker setup is a solid foundation for developing and deploying your enterprise RAG application locally or as the basis for Kubernetes deployment later.

# Better Enterprise Design

Instead of directly using `ChatOllama`, create an abstraction.


models/
│
├── llm_factory.py
├── ollama_model.py
└── gemini_model.py


Example:


from config import settings

if settings.LLM_PROVIDER == "ollama":
    llm = OllamaModel()

elif settings.LLM_PROVIDER == "gemini":
    llm = GeminiModel()


Then your `RAGService` simply does:


llm = get_llm()

answer = llm.invoke(prompt)


Now you can switch providers by changing only:

ini
LLM_PROVIDER=gemini


or

ini
LLM_PROVIDER=ollama


without modifying the rest of the code.

def ask_question(question: str):

    # 1. Check Redis first
    cached_answer = get_cache(question)

    if cached_answer:

    # 2. Search FAISS
    docs = retriever.invoke(question)

    # 3. Call Ollama
    response = llm.invoke(prompt)

    answer = response.content

    # 4. Save in Redis
    set_cache(question, answer)

    return answer

## How it works


User Question
      │
      ▼
Check Redis Cache
      │
 ┌────┴────┐
 │         │
Hit       Miss
 │         │
 ▼         ▼
Return   Search FAISS
Answer        │
              ▼
        Generate Answer
              │
              ▼
      Store in Redis
              │
              ▼
        Return Answer


This integration caches answers to repeated questions, reducing response time and avoiding repeated FAISS retrieval and LLM inference. For a production application, you would typically generate cache keys (for example, by hashing normalized questions) instead of using the raw question text directly, and you would add error handling around Redis operations so the application continues to work if Redis is temporarily unavailable.
